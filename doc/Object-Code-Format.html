Appendix D Object Code Format ¶

Objects use the portable XOROBJ2 format. The eight-byte magic XOROBJ2 followed by a newline identifies the format version; an incompatible format requires new magic. All table fields are unsigned 32-bit little-endian words. Values retain signed 32-bit arithmetic; payload blobs preserve their counted byte lengths.

The checked header describes ten tables: blobs, files, source locations, definitions, expressions, extents, anchors, operand fixups, fragments and RAM allocation identities. Table offsets, counts, ownership, references, reserved fields and payload bounds are validated before linking. The reader rejects old object formats; rebuild them from assembly source.

Files carry locations needed for diagnostics, captured character maps and expression graphs. RAM records retain source label order for the specified allocation permutation. Code fragments and operand fixups use the same layout and encoder as direct binary assembly. Source-time expansion and sizeof are completed by the assembler.

The exact header, record widths, tags, validation rules and example are documented in doc/object-format.md, installed with the tools.
