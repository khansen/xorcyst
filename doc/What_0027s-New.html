1 What’s New ¶

Unreleased ¶

  • Binds local-label references in saved .equ, .define and = expressions to the namespace where the alias is defined, including macro expansion namespaces. This fixes forward uses in operands and storage counts and deliberately changes compatibility with version 1.9.7: later uses from another local-label scope now refer to the definition’s local label, rather than the use’s local label. Such uses can produce different bytes, or fail if the local label is absent from the definition’s scope. Repeating an .equ or .define in another scope can now warn that its definition differs and retain the first definition. Ordinary = reassignment remains supported.
  • Local-label aliases whose values can be resolved now appear in the text listing’s symbol table; .equ and .define aliases also have values in cross-reference symbol definitions. This includes aliases that already assembled successfully in version 1.9.7.
  • Rejects = assignments to non-constant symbols with a located error, preserving their original definitions and existing output files. Labels, procedures, types, macros and data variables can no longer silently ignore a replacement or leak its expression. Ordinary constant reassignment remains supported.

Version 1.9.7 ¶

  • Evaluates $ in cross-reference data expressions at each operand’s address, including successive operands in the same directive. Valid input such as L1: nop / .word $-L1 now assembles with --xref-data, and the reported emitted values match the binary. Binary and object generation are unchanged.
  • Frees a constant’s previous expression when an = assignment replaces it, including repeated assignments in loops. Values already captured by operands and analysis records keep their existing behavior.
  • Removes undefined signed shifting when the linker sorts data labels for RAM allocation. Zero-page constraints, alignment and size keep their existing priority, with the same linked addresses.

Version 1.9.6 ¶

  • Avoids crashes while computing addresses for zero-page optimization or late storage counts in expressions such as Fwd+(L2-L1-1), where Fwd is a forward label and the label difference becomes zero. Arithmetic identities now wait for unresolved operands; completed expressions retain their normal bytes and addressing modes. Invalid shifts in these operands report their source error without crashing or replacing output.
  • Preserves negative 32-bit integers when loading object expressions and exported constants on 64-bit hosts. Relocated comparisons, arithmetic and storage counts no longer treat these values as large positive integers. Compact 8-, 16- and 24-bit positive values retain their existing interpretation. The object format and emitted object bytes are unchanged; existing objects can be linked with the corrected reader. In-range negative relocated instruction operands now link, and negative byte/word data no longer produce spurious truncation warnings. For example, lda #(L2-L1+-2) with adjacent labels emits A9 FF.
  • Defines >> consistently as a logical 32-bit right shift in constant folding, binary address evaluation, listings, analysis outputs and linking. Negative exported constants keep the results of local constant expressions: (-2)>>1 is $7FFFFFFF, and (-2)>>31 is 1. This deliberately changes formerly sign-filling negative label expressions in binary output and some previously successful links. A shift count must be 0–31; link-time counts of 32 or more are now rejected even on 64-bit hosts. A zero shift retains the signed 32-bit value. Listing bytes, symbol values and instruction records follow this same rule; diagnostic listings treat invalid shifts as unevaluable instead of executing an undefined shift. Invalid shifts in data or instruction operands retain their source-located errors and diagnostic listings when cross-reference data, instruction records or FCEUX names are requested. Storage counts with FCEUX ROM export remain an exception: an unevaluable or negative extent prevents complete output-path planning, so analysis collection fails and suppresses the diagnostic listing. A late negative count can also lose its source-located range error, leaving only could not collect assembly analysis and exit status 3 even without a dependency manifest. Omit ROM export to obtain the ordinary diagnostic; this limitation is tracked in TODO.
  • Checks lower as well as upper bounds on relocated linker operands. One-byte instruction operands must fit -128–255, two-byte operands -32768–65535, and zero-page addresses 0–255; relative branches retain their signed displacement check. Out-of-range instructions fail without replacing output. Byte and word data outside their signed/unsigned ranges warn before truncation, including negative values; diagnostics print negative values in signed decimal and nonnegative values in full hexadecimal.

Version 1.9.5 ¶

  • Keeps procedure symbol definitions valid after procedure bodies are flattened. Instruction xref and separate instruction records can analyze procedure references, including procedures containing dotted member accesses, without reading freed memory. Bindings retain the original procedure declaration location.
  • Validates mask namespaces and record layouts without crashing. Known named record widths are resolved in the declaration’s constant scope, even when a field has the same name. Widths must still be known when the record is declared; later assignments do not change an existing record layout. Forward aliases to record masks now resolve to the correct mask instead of zero; for example, M .equ mask R::lo before the record declaration resolves correctly when used afterward.
  • Rejects recursive sizeof layouts with a diagnostic instead of crashing or repeatedly expanding them. A structure or union cannot use its own unfinished size. Size ancestry also covers storage behind a label; repeated independent uses and nested completed types remain supported.

Version 1.9.4 ¶

  • Checks the final value of late zero-page operands in pure-binary output. If an operand becomes negative or exceeds $FF after address calculation or shortening, assembly fails without replacing existing output, matching the linker check. Signed immediates, branch offsets, explicit indirect operands, forced-wide instructions and the existing handling of literal byte operands are unchanged.
  • Resolves named constants in copied S::member offsets, preventing incorrect local-symbol references in objects and crashes in binary address evaluation. Nested layouts, forward aliases and link-time counts are supported. Cycles through scoped field offsets are rejected, including mutual layout cycles and uses through sizeof; references to earlier offsets of the same type remain valid. Completed integer offsets are cached within each evaluation, preventing repeated expansion of shared offset dependencies. Unresolved link-time offsets still expand as expression trees.
  • An explicit S::member now captures a known reassignable = count at its use site, matching explicit sizeof(T). Previously it could use the final value. Other type-layout paths can still use the final value; reassigning counts does not define a single fixed layout for a type.
  • Rejects unsupported expressions during object encoding, reports their source location, and preserves the previous output file. This prevents invalid objects with excess initializer braces, unresolved forward local-label aliases, or dotted references inside another member’s index from being published with a successful exit status. Forward local aliases and nested dotted indexes still need earlier resolution to support their valid forms.
  • Fails object generation when its table exceeds 16384 distinct expressions, preserving the previous output file instead of publishing an object with invalid expression indexes. Duplicate expressions reuse existing entries even when the table is full. Unsupported internal operators and statements also count as generation errors.

Version 1.9.3 ¶

  • Recalculates relocatable code labels and subsequent unit origins after linker zero-page shortening, repeating layout when needed at the $100 boundary. Preserves forced-wide instructions and explicitly assigned label addresses. If a final zero-page operand becomes negative or exceeds $FF, linking fails without publishing output; negative immediates and signed branch offsets remain supported.
  • Preserves late zero-length omitted and uninitialized structure-array fields, including nested deferred layouts. These use field padding with a minimum count of zero, including label-difference counts in binary output and forward constants. Late negative counts remain invalid in object output. Known positive counts keep direct expansion. The positive-count rule for standalone storage, including the outer count of .T[n], now also applies to late counts in both output modes; some late zero counts accepted by 1.9.2 are now rejected. Explicitly initialized user-type arrays require positive counts.
  • Validates late PC- and address-dependent binary storage counts and rejects sizes that change after address calculation, preserving the previous output file. Keeps unresolved binary storage statements separate so each uses its own PC and range check; valid zero field remainders remain supported. Known-count object grouping is preserved; late label-based omitted-array counts can use conditional size expressions.
  • Documents existing PC-capture limitations: .equ $ and = $ can retain a provisional first-pass address after deferred storage, including newly supported late-zero arrays. Use a label for the final address. Both outer omitted-array counts and nested field counts that depend on $ can differ between binary and object output. Binary output evaluates the outer remainder after the first element, which can change layouts from 1.9.2; object output evaluates $ at the start of merged storage.
  • Resolves named constants in copied structure-size expressions, so indexed member references use the correct element stride in object output, including nested members and external instances.
  • An explicit sizeof(T) now captures a known reassignable = count at the line where sizeof is used, as initialized instances do. Previously it used the final value. Index strides, uninitialized allocation and member offsets can still use the final value; reassigning counts does not provide a single fixed layout for a type.

Version 1.9.2 ¶

  • Retains labels reached through forward aliases in storage and field counts before unused-label removal, so requesting a listing or analysis output no longer changes whether these counts assemble.
  • Reports invalid dotted references without crashing, including nested members and references introduced by forward aliases in storage counts or operands. Clears removed label definitions and prevents validation from visiting freed expressions.
  • Rejects unresolved or invalid storage expressions instead of silently dropping binary storage or writing invalid objects. Preserves PC-based binary counts and valid link-time object counts, including external symbols introduced by aliases.
  • Validates deferred storage counts in direct storage and omitted or built-in array fields before merging and object encoding. Preserves zero-length omitted fields in initialized and uninitialized structures, empty explicit built-in initializers, and zero-size user types. Deferred zero counts for omitted structure-array fields remain unsupported; standalone storage still requires a positive count.
  • Resolves forward constant aliases in ordinary operands and sizeof label data, with cycle detection and validation of the symbols at the end of a chain.
  • Accepts previously defined named counts in unions, in the constant scope, and avoids secondary errors when a union declaration is invalid. Union dimensions must still be known at declaration time.
  • Caches completed integer aliases within each evaluation and avoids repeated statement-list scans when expanding aggregates and merging adjacent data.
  • Encodes numeric .char data and relocations as bytes in objects. Numeric characters remain independent of the character map, which applies to strings. Out-of-range numeric characters now warn in object output as they do in binary output.

Version 1.9.1 ¶

  • Validates deferred counts of explicitly initialized user-type array fields before storage merging and object encoding. Rejects zero and negative counts, including counts defined after an instance, without replacing existing output.
  • Resolves aliases and unary expressions in these counts, detects circular definitions, and preserves values already known when an instance is expanded.
  • Removes zero padding before object encoding to avoid spurious 256-byte fills. Preserves adjacent storage grouping and listing source locations for previously correct inputs, including nested arrays and omitted subfields.
  • Reports field-specific errors for invalid named counts, matching literal-count diagnostics without cascading errors after an invalid initializer kind.
  • Preserves listing schemas and instruction-record schema version 3. Other storage-count paths, ordinary-operand aliases and named union counts remain tracked in TODO, along with resolver and aggregate-instance performance work.

Version 1.9.0 ¶

  • Preserves the declared size of explicitly initialized user-type array fields in structures and unions by initializing the first element and zero-filling the rest. Improves invalid-count diagnostics and avoids cascaded padding errors.
  • Continues assembly after empty initializer expansions and taken conditional branches, preserving following labels and data and avoiding assertion aborts after repeated initializer errors. Releases unused structure fill expressions.
  • Adds opt-in --listing-version=2 for pure-binary JSON/NDJSON listings, with segment, byte-count and emission metadata, compressed storage fill, and emitting spans that partition the binary. Diagnostic listings do not claim bytes from a previous output file.
  • Accounts for numeric .CHAR data in listing v2 and warns when an explicit listing version has no listing destination. Documents offset joins and CPU-address wraparound.
  • Preserves default listing v1 output and instruction-record schema version 3. Named and deferred user-type array count limitations remain tracked in TODO.

Version 1.8.2 ¶

  • Restores documented omitted fields in structure, union and record initializers, preserving field positions, zero padding, nested initializers and macro expansion.
  • Corrects padding for omitted user-defined fields and anonymous unions, and fixes assertion aborts for .CHAR storage, omitted .CHAR fields and short strings.
  • Reports a specific diagnostic for unsupported gaps inside built-in array initializers.
  • Adds 16 regression tests covering emitted bytes, linked objects, character maps and label/listing/xref addresses after padding. Output schemas are unchanged.

Version 1.8.1 ¶

  • Corrects structured-listing binary offsets after code-segment storage and non-emitting data-segment initialized data or .INCBIN.
  • Preserves CPU addresses, assembled bytes and diagnostics, with 28 regression subcases across listing formats and debug modes.
  • Keeps listing schema version 1 and instruction-record schema version 3. Non-emitting data-segment rows still lack per-row emission metadata; see TODO.

Version 1.8.0 ¶

Analysis consumer migration required: instruction records now use schema version 3. Every span’s file is an integer index into a shared files table; older schemas are no longer emitted. See XASM_INSTRUCTION_RECORDS_V3_SPEC.md and XASM_INSTRUCTION_RECORDS_V2_SPEC.md for the migration contract.

  • Adds explicit memory-access facts and signed additive operand terms with per-use symbol bindings.
  • Corrects read-modify-write, BIT/CMP, pointer, and immediate access classifications across cross-references and analyses.
  • Reduces instruction-record size and serialization cost, and enforces a performance limit in the real-project comparison tool.
  • Installs generated xasm/xlnk man pages and a worked analysis-feature guide.

Version 1.7.0 ¶

  • Adds structured listings, cross-references, instruction records, dependency manifests, and binary comparison.
  • Exports FCEUX ROM and RAM debugger names, including banked programs and optional 16 KiB NROM mirroring.
  • Improves parser, symbol-table, AST, and analysis performance.
  • Checks assembler and linker output failures, symbol allocation failures, and malformed inputs.
  • Ships the regression suite and feature specifications, with archive and installation validation on Linux and macOS.

  • Fixed bug in processing of array of operands to DB, DW, DD directives (some high-level constructs were only reduced in first item).

Version 1.4.0 ¶

Assembler

  • Added --debug switch (short form: -g). When this switch is given, the assembler will retain file and line information in the object file, which the linker can use to produce more descriptive link-time warning and error messages.
  • LABEL directive can take a specific address as argument, so that “pointers” can be made to any part of memory (i.e. you can address memory location $200 as a structure (or array of structures), without having to explicitly define storage for it).
  • Constraints can be communicated to the linker on how contents of data segments should be mapped to RAM; see section 3.2.19, “Controlling data mapping”.
  • PUBLIC modifier can be specified directly when defining a variable.
  • Fixed a bug in code generation of exported string constants.

Linker

  • Uses the information generated from the assembler --debug switch to produce descriptive warning and error messages.
  • Rewrote data segment mapping function to take zeropage and alignment constraints into account.
  • Improved code relocation; as a result, the current PC ($) can be used freely in any expression, and the origin argument for the pad command works.
  • Fixed a linker script parsing bug.

Version 1.3.5 ¶

Assembler

  • Added ability to declare storage for array of user-defined types, C-style (works for native types too).
  • Added ability to specify the type of data that a label addresses.
  • Fixed bug in code generation of storage of user-defined types.
  • Fixed some error detection and parsing woes.
  • Added DEFINE directive (same semantics as EQU, but potentially more compact).

Linker

  • Fixed a bad code relocation bug.
  • Implemented bank operator (^).
  • --verbose switch now gives helpful info on what the linker is doing.

Version 1.3.0 ¶

  • Added support for user-defined records (RECORD directive, MASK operator).
  • Added WHILE directive.
  • Implemented ELIF directive.
  • Improved --define switch: A value can now be assigned to the identifier (i.e. --define a=10).
  • SIZEOF operator now works on variable identifiers too.
  • Fixed bug that prevented single-character identifiers from working.
  • Added --no-warn switch to suppress assembler warnings.
  • Early support for --verbose switch.

Version 1.2.0 ¶

  • Added support for forward/backward branches (-, --, +, ++, and so on, up to eight levels (++++++++)).
  • Fixed bug that caused the assembler to run out of file handles when including a large number of files.
  • Fixed bug that caused .db <a, >b and other lines with < > to be parsed erroneously.

Version 1.1.0 ¶

  • Full support for user-defined types: Structures, unions and enums.
  • Better separation of symbol types. In the previous versions, everything was a label. The assembler now distinguishes properly between labels, procedures, variables, constants and user-defined types.
  • Support for anonymous macros (rept directive).
  • Crash-bug fixes (if directive, incbin directive).
  • Preliminary support for --define=IDENT assembler switch (can be used in ifdef and ifndef directives).
  • Added message directive.
  • Improved literal expression folding. "hello " + 123 will now be folded to "hello 123".
  • Added assembler switch --swap-parens, which swaps the operators used for indirection from [ ] to ( ).
  • Syntax of extrn directive changed slightly: Must now specify the symbol type.
  • Relaxed syntax of db, dsb and similar directives. If no expression is given as argument, a single item is allocated.
